# Click

[English](README.md)

为 macOS 编写的原生按键映射与宏工具。按设备配置，关闭窗口后继续在菜单栏后台运行。

![Click 宏编辑器](docs/images/macros.png)

## 功能

- **按设备映射。** 每把键盘独立配置，将按键映射到另一个键或可复用的宏。
- **宏编排。** 按顺序切换应用、等待、发送快捷键、输入 Unicode 文本，可调整步骤顺序。
- **载入与导出。** 带版本号的 JSON 保存设备、映射和宏；载入后先编辑，保存后生效。
- **后台运行。** 关闭窗口后继续工作，在菜单栏暂停服务、停止宏或退出。
- **登录自启动。** 在设置中开启，macOS 可能要求在登录项设置中批准。
- **原生编辑器。** 紧凑侧栏、行式映射表和有序宏编辑器。切换语言会即时更新界面与菜单，并保留未保存的编辑。
- **本地运行。** 无账号、网络服务、Shell 执行、分析统计或按键历史记录。

## 安装

需要 **macOS 14 或更新版本**。界面默认使用 **English**。在 **Settings → Language** 中切换 English 或简体中文，应用会记住选择。

从 [Releases](https://github.com/MrCroxx/click/releases) 下载符合 CPU 架构的应用，解压后将 **Click.app** 放到 Applications，再授权和启用登录项。构建采用临时签名，未经过 Apple 公证；也可以从源码构建。

1. 打开 Click，在设置中按需授予**辅助功能**与**输入监控**权限。
2. 点击**添加设备**，选择已连接的键盘，添加映射。
3. 若要使用宏，先在宏编排页创建步骤，再把宏分配给按键。
4. 打开设备的**启用映射**，点击**保存**。
5. 按需开启**登录时启动**。

新添加的设备默认不启用映射。保存只应用已启用的配置。暂停会恢复原有键位；启动会恢复最近保存的配置。关闭窗口保持后台运行，退出会恢复映射并停止服务。

## 构建

需要 macOS 上的 Swift 6 工具链，以及 Xcode 或 Command Line Tools。

```sh
make test
make dev
make release
```

`make release` 生成 `build/Click.app` 和当前构建机架构的 `build/Click-macOS-<arch>.zip`。设置 `SIGNING_IDENTITY` 可以使用自己的签名身份。以下命令用示例数据预览界面，不访问键盘：

```sh
make demo
```

`Click.app/Contents/MacOS/Click --background` 启动时不打开窗口。应用是**用户会话中的后台服务**：通过 `SMAppService.mainApp` 登录启动，按键操作依赖已登录的图形会话，不是登录前运行的 root LaunchDaemon。崩溃后需重新打开应用，目前没有独立看门狗。

## 配置与恢复

文件保存在 `~/Library/Application Support/Click/`：

- `config.json` — 经过校验并原子保存的配置，仅当前用户可读写。
- `recovery.json` — 系统修改前写入的原有 HID 映射及 Click 应用的映射。

设备通过厂商、产品和序列号识别；没有序列号时使用连接位置。无序列号设备更换 USB 接口后可能需要新配置。具有相同身份的多个键盘接口共享配置。每两秒检查设备变化，在连接变化后重新应用保存的映射。

暂停、正常退出或崩溃后的下次启动时，Click 恢复仍属于自己的映射，保留其他软件做的无关修改。强制结束进程后，映射可能保留到重新打开 Click、断开键盘或重启系统。恢复前请勿删除恢复文件。损坏的配置或恢复文件会显示错误，不会被静默覆盖。导出的配置可能包含设备序列号和宏文本，公开分享前请检查。

## 当前边界

- 支持普通键盘页按键，包括左右修饰键。暂不包含 Fn、媒体键、鼠标按钮、手势或设备固件编程。
- 映射由单个物理键触发，不支持组合键触发。宏可以输出组合快捷键，修饰键不能触发宏。
- 宏使用 **F13–F20 保留通道**，所有配置合计最多启用 **8 个宏触发键**。其他键盘上对应的功能键也会触发这些宏，因此启用期间不要把它们用于其他快捷键。普通一对一映射不占用通道。
- 映射基于物理键位。Unicode 文本是独立宏动作，在安全输入框或拒绝合成事件的应用中可能无效。
- 同时只执行一个宏，自动重复与重叠触发会被忽略。应用激活最多等待五秒。切换应用后，在每个后续步骤前确认前台应用，不一致则停止。已经提交给 macOS 的应用启动请求无法通过取消撤回。
- 接管实体设备的键盘工具（如 Karabiner-Elements）可能使原生 HID 映射无法生效。请关闭其他工具对 Click 所管理键盘的接管；虚拟键盘会作为独立设备显示。
- 底层使用 Apple 的 `UserKeyMapping` 和 Core Graphics 事件监听。系统或设备权限限制可能拒绝映射；Click 会检查写入结果并读回验证，不安装特权助手绕过限制。安全输入模式可能阻止宏拦截，不应在密码输入中依赖宏。
- 登录权限、实体按键输出、蓝牙重连、安全输入行为需要在目标 Mac 上验证。自动测试通过模拟应用和输出适配器验证配置、恢复和宏顺序，不代表硬件实测通过。

## 开发

`ClickCore` 包含配置结构、键码表、映射编译和按所有权恢复逻辑；`Click` 包含 SwiftUI 编辑器、AppKit 菜单栏、HID 后端、宏执行器及登录项集成。CI 执行测试并上传应用压缩包。

翻译集中在 `Sources/ClickCore/Resources/Translations.json`。新增语言时在 `AppLanguage` 中声明，并提供相同的键和格式参数；本地化测试会检查完整性。应用包包含语言资源。系统原生对话框使用 macOS 语言偏好。

架构参考了 [Olanzi](https://github.com/MrCroxx/olanzi) 的原生宏和生命周期实现；本项目使用独立 UI 和通用键盘后端。相关 Apple 文档：[按键映射](https://developer.apple.com/library/archive/technotes/tn2450/)与[登录项注册](https://developer.apple.com/documentation/servicemanagement/smappservice/register())。
